# 📦 Change Log

> **Versioning convention:** `XX.0.Y.Z` — `XX` BC major version, `Y` feature release, `Z` patch.
> **Date format:** `DD/MM/YYYY`

---

## ✨ Version 28.0.2.0 — 17/09/2026
- [Feature] **AI-assisted matching.** The cases the deterministic rules deliberately left unmatched — several invoices of the same amount, a reference the engine could not confirm, a balance already partly settled — are now offered to an AI agent before the residual FIFO runs. The agent is given only the movement and the candidates the engine had already shortlisted, and it answers one question: which of them do the documents actually identify?
- [Feature] Groups the AI resolves are ordinary application groups, shown with match method **AI Assisted** and keeping the candidate type that explains which doubt was resolved. They are reviewed, adjusted and posted like any other group.
- [Feature] Everything the AI proposes is validated again before a group exists: the movement must have been one of the candidates offered, still be open, still have balance, and never be allocated beyond what is left.
- [Feature] **Ledger Application Setup** gains an **AI Matching** section: a switch, off by default, and one confidence per kind of doubt resolved.
- [Note] When AI matching is off, unavailable or unsure, proposals are generated exactly as in 28.0.1.0. Nothing about the deterministic rules changed.
- [Note] Requires the **AI Integration** extension (Deloitte) and an LLM endpoint configured in **AI Models Setup**. The assistant registers itself on install and on upgrade; **Register AI Assistant** in the setup re-runs it on demand.

## ✨ Version 28.0.1.0 — 15/09/2026
- [Initial] Initial Version.
- [Feature] **Create Application Proposal** on Customer Ledger Entries and Vendor Ledger Entries analyses every open movement of that customer or vendor and proposes how to apply them.
- [Feature] **Application Proposals** list shows the proposal history and the active proposal of each customer and vendor.
- [Feature] Proposals are shown as a tree: the movement that settles at the top, the movements it settles indented below it, with the amount proposed for each one.
- [Feature] Proposals are generated by five ordered rules — explicit reference, exact one-to-one, exact one-to-many, standard payment tolerance and residual FIFO — and every group shows how it was found and how reliable it is.
- [Feature] Cases where two different matches would be equally valid are left unmatched on purpose and flagged as candidates for a future AI-assisted phase.
- [Feature] Movements can be added to or removed from any group that has not been registered yet, and the group is marked as manually modified.
- [Feature] **Post** registers one application group and **Post All** registers every pending group; a group that fails does not undo the ones already posted, leaving the proposal partially registered.
- [Feature] A proposal is automatically marked obsolete when the ledger entries it was built on change, and can then no longer be registered or edited. Its own postings never make it obsolete.
- [Feature] Proposals that never posted anything can be deleted; proposals that did are kept for audit.
- [Feature] **Ledger Application Setup** tunes the matching limits and the residual FIFO, and shows the standard payment tolerance values with a shortcut to the standard change process.
- [Feature] Permission sets *Ledger Application Assistant - Admin* and *Ledger Application Assistant - User*.
